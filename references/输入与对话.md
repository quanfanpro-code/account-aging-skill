# 对话与输入约定

用户只需提供账表、截止日期和业务要求。agent负责识别表头、准备下面的配置、运行脚本、解释结果；不要把JSON、命令行、内部行号或逐项技术设置交给用户填写。

## 必要资料

序时账：日期、科目编码、科目名称、明细名称（统一后的结算客户/供应商）、借方金额、贷方金额。凭证号用于自动对应同凭证的票据转科目；票据类型和票据号可提高判断与核销准确性。

期初：科目编码、科目名称、明细名称、借方余额、贷方余额，可附期初账龄分档。用户明确有完整历史、期初为0时，设置`zero_opening=true`，不再索取期初表。不能仅因没有提供期初就自行假定为0。

## 配置示例

```json
{
  "input": "C:/项目/已清理序时账.xlsx",
  "journal_sheet": "整合序时账",
  "journal_columns": {"科目路径":"科目名称", "往来单位":"明细名称", "借方":"借方金额", "贷方":"贷方金额"},
  "zero_opening": true,
  "cutoffs": ["2025-12-31", "2026-08-31"],
  "include_receivable_bills": true,
  "output": "C:/项目/往来账龄.xlsx"
}
```

输入已存在“科目名称”时，不再把其他列映射成同名列；先选择一套唯一映射。示例需按真实表头调整，不可机械套用。

默认分档按365天一年：1年以内、1—2年、2—3年、3—4年、4—5年、5年以上。可配置`buckets`天数区间和同数量的`bucket_labels`。区间连续，边界归前档。期初日期使用`opening_date`，期初分档使用`opening_aging_columns`，每项包含`lower`、`upper`和`column`。

## 决定由agent组织

1. 执行`inspect --config 配置文件`，读取结构化结果，不把整段技术返回直接发给用户。
2. `needs_decisions`：结合账表核实疑似同单位名称、暂估归属。记录`name_decisions`（每项含`names`两种原名称、`canonical`统一名称或null表示分别计算）及`temporary_assignments`（编码到归属科目）。重要主体判断不能只凭文字相似自动合并。
3. `needs_bill_decisions`：读取关联原账行、类型、金额。先核查资料；仍缺少影响口径的信息时，以具体单位、凭证和金额集中询问。记录`bill_decisions`，每项含`转出行`、`转入行`、`金额`、`连续计龄`布尔值、`依据`。跨凭证但同日的关系可明确指定；不同日期不能盲配。
4. `ready`表示预览已可核对。确认与用户已授权范围一致后执行`calculate`，交付一份最终工作簿。

纯数值、日期、表头错误应先由agent核查原资料；不要一律退给用户核实。不能把agent的证据判断冒写成“用户已确认”，依据应如实写明。

## 摘要中的暂估

正常往来科目不必人为改名为暂估。计算核心读取摘要中的暂估和冲回字样，并输出“暂估识别依据”。未写暂估的冲回，须明确引用原凭证，且在同单位、同科目中唯一对应到较早暂估新增，金额不超过该笔新增；跨年重号或多笔可能对应时不自动猜测。实际付款、退货按真实核销处理，收到正式发票的新增不再标作暂估。agent应核对未能自动关联但摘要显示冲销的具体业务，不把未识别等同于不存在暂估。

源账单位字段缺失但摘要明确写出名称时，agent可在计算输入中据实补入，并保留原账行、原摘要和补入理由；不覆盖源账。完整归一化仍按下节范围执行。

## 失败时的定位与继续条件

| 触发情况 | 先做什么 | 仍不能解决时 |
|---|---|---|
| 列映射后重名、缺少必需列 | 回看原表，只保留一套唯一映射；不删真实数据凑列 | 说明缺失字段、所在表及其影响，索取具体资料 |
| 日期、金额不能读取 | 定位原账行，核对原值及记账格式，有依据再整理输入 | 保留原值和位置，暂停受影响部分，不把错误金额填零后继续冒称完成 |
| 暂估冲回未自动识别 | 查摘要引用的原凭证、单位、日期和金额；将有据的输入处理留痕 | 不强配，说明对应不唯一或缺失的原始记录 |
| 票据余额不足或跨日关联 | 查原债权来源、票据号、期初和截止日，确认不是列映射错误 | 说明具体客户、金额和现有边界，不虚构期初、不拿未来记录补齐 |
| 结果余额或分档不一致 | 回查发生额、重分类及对抵记录，修复后重新计算和回读 | 不交付为最终结果，明确已核对及受影响的范围 |

不要为每个技术步骤重复询问授权。沿用本次对话已明确的口径；仅剩影响结果且无法从资料查明的关键判断才集中询问。返回的内部状态只供助手处理，不整段抛给用户。

当前仅保留原程序的名称候选确认能力，完整归一化不在本轮开发。用户另写的归一化技能确定后，将其实际代码和资源纳入本仓库，并更新来源与验证；在未提供之前不声明已经内置，不在运行时指向其他机器的技能路径。
